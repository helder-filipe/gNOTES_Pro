1. Guardar uma cópia da versão atual

Na aplicação anterior, usa Backup para descarregar as notas. Guarda também uma cópia da folha de cálculo e do Apps Script atual.

Os ficheiros originais fornecidos não foram alterados. Esta pasta contém a nova versão, preparada separadamente.

2. Atualizar o Apps Script

  1. Abre a folha de cálculo das notas. Entra em Extensões → Apps Script.
  2. Substitui o código antigo pelo conteúdo de zettelkasten apps script.txt (igual a Apps-Script.gs). Evita manter duas definições de doGet ou doPost.
  3. No início do código, podes indicar o nome exato da aba das notas em NOTES_SHEET_NAME. Se existir apenas uma aba com ID, Titulo e Conteudo, a identificação é automática.
  4. Guarda e atualiza a implementação da aplicação Web: Implementar → Gerir implementações → Editar → Nova versão → Implementar. Mantém o acesso autorizado que já utilizas. Os nomes dos menus podem variar com o idioma da conta.
  5. Se o endereço /exec mudar, copia-o para Preferências e cópias → Ligação ao Google Sheets na nova aplicação.

O script acrescenta as colunas necessárias na primeira gravação, preserva os identificadores existentes e cria duas abas auxiliares: _gnotes_operations para confirmações e _gnotes_history para versões anteriores. Não elimina linhas de notas.

Depois desta atualização, usa a nova interface para escrever. O servidor mantém a leitura da versão antiga, mas recusa as suas gravações sem controlo de versão. Isso evita que a aplicação anterior substitua notas sem verificar conflitos.

3. Abrir a nova interface

Para experimentar no computador, abre index.html. Para substituir a interface alojada, publica todos os ficheiros desta pasta, incluindo vendor, no alojamento que já utilizas. Não basta copiar apenas o HTML.

A ligação original já está preenchida. Até atualizares o Apps Script, poderás ler as notas e guardar alterações no dispositivo; aparecerá um aviso de que a sincronização precisa de atualização.

Quando vires Sincronização confirmada, a fila foi enviada e confirmada. Se estiveres sem ligação, continua a escrever: as alterações mantêm-se na fila até à próxima tentativa.

Notas práticas

  • Cópias: o JSON completo inclui o lixo, o histórico local, os rascunhos e a fila. O ZIP para Obsidian inclui as notas ativas. Os ficheiros Markdown usam o ID como nome para manter ligações estáveis.
  • Importação: aceita o JSON antigo. Notas existentes com conteúdo diferente são importadas como cópias; não são silenciosamente substituídas.
  • Dispositivos: notas e revisões sincronizam através do Sheets. Rascunhos, temas e notas fixadas pertencem ao navegador em que foram criados. Não apagues os dados do navegador enquanto houver alterações por enviar.
  • Modo offline: a interface pode ficar disponível após uma primeira visita em HTTPS ou localhost. Imagens externas e a sincronização continuam a precisar de rede. Ao abrir o ficheiro diretamente, as bibliotecas estão na pasta, mas não existe instalação PWA.
  • Conflitos: «Preservar ambas» mantém a nota do servidor e cria uma cópia da versão local. «Usar versão do servidor» guarda a versão local no histórico antes de a substituir.
  • Google Sheets: altera as notas através da aplicação para que a versão seja atualizada. Alterações manuais nas células não incrementam automaticamente o contador de versão.
  • Acesso: este código mantém o modelo de acesso do teu Apps Script. Não acrescenta um sistema de contas próprio nem torna a publicação privada por si só.
  • Limites: o editor aceita até 40 000 caracteres por nota. O grafo mostra até 120 notas por filtro; usa uma categoria para explorar bibliotecas maiores. A lista e o sincronizador usam a biblioteca completa, pelo que bibliotecas muito grandes podem precisar de paginação futura.
  • Referências e multimédia: as imagens são apresentadas e os recursos abrem no respetivo site. A captura procura automaticamente o título e a capa. No editor, acrescenta uma ligação em «Fontes, recursos e ligações» e aguarda a consulta automática, ou usa «Obter capa da ligação». O YouTube fornece miniaturas dos seus vídeos; os restantes sites são consultados através do Microlink, que recebe a ligação pública, mas não o texto da nota. Sites privados, bloqueios e limites do serviço podem impedir a obtenção. Nesse caso, podes indicar uma imagem manualmente. Uma imagem já preenchida é preservada. Usa «Procurar outra capa» para a substituir: o endereço só é trocado se a nova imagem carregar. Se falhar, aparece «Capa indisponível», sem ícone de imagem partida. Guarda a nota para sincronizar a capa. As ligações do Instagram podem expirar; esta aplicação guarda o endereço, não uma cópia permanente da imagem. Voltar a consultar pode obter uma ligação nova, mas depende de o Instagram permitir o acesso. Uma preservação permanente requer guardar uma cópia num armazenamento próprio.

Atualização: capas e IQR

Substitui os ficheiros da aplicação pelos desta pasta, incluindo metadata.js. Se já instalaste o Apps Script desta versão, não precisas de voltar a implementá-lo. A ligação ao teu Google Sheets foi mantida.

O IQR voltou à lista, à leitura e ao editor, com ordenação «Maior IQR» e uma explicação dos pontos. Mantém os pesos originais: texto até 50, origem até 35, ligações até 60 (120 nos mapas), etiquetas até 15, imagem +2, recurso com menos de 30 palavras −15, edição até 30 e leitura até 15. Os pontos são normalizados por 202, ou 267 para mapas de conteúdo. Os tempos já guardados são considerados. O IQR é calculado, não exige uma coluna nova.

Níveis: Superficial abaixo de 30; Consistente a partir de 30; Elevada Qualidade a partir de 50; Académica / Profunda a partir de 70. As ligações reconhecem identificadores, títulos e aliases; «Mapa de conteúdo» recebe os pesos de MOC.
